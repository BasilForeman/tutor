# Tutor CRM — план реализации

## Дополнение: ручной сценарий Сони

Добавлена возможность начать **➕ Новая передача** без предварительно заведённых сущностей: выбрать существующую заявку либо ввести данные вручную. При подтверждении активные ученик, репетитор и источник находятся по имени без учёта регистра; отсутствующие записи и заявка создаются в транзакции с передачей и историей статуса. Потерянная заявка повторно не используется. Это устраняет блокировку первого практического сценария, не меняя комиссионные правила и архитектуру.

Проверка: 60 unit-тестов прошли, включая создание отсутствующих сущностей одной транзакцией, повторное использование активных записей без перезаписи контакта и пустой ввод. `compileall` и `git diff --check` также прошли. Интерактивный Telegram прогон этой новой ветки не проводился.

Приоритеты следуют `PROJECT_SPECIFICATION.md`. Существующие staged-изменения считаются пользовательской работой: перед правками сохранять их и изменять только необходимое. Миграции и запуск приложения делать только на отдельной тестовой БД. Секреты не копировать и не раскрывать.

Trial/cancelled исключены из начислений; частичные/полные оплаты ограничиваются остатком.
- **Новые:** `bot/services/lessons.py`, `bot/handlers/lessons.py`, keyboards/states; `bot/services/finance.py` (реализован для короткого закрытия); `bot/services/payments.py`, handlers/states; модели `Lesson`, `AssignmentAdjustment`.

Досрочное закрытие стандартного режима после 1–4 занятий оставляет append-only adjustment в размере 25% от заработка; percent mode фиксирует процент от заработка. Фиксированные/ручные/абонементные договорённости при закрытии сохраняются.
- Каждая связанная операция в транзакции; история не перезаписывается.

PostgreSQL 17 одноразовая БД прогнала миграции 0001–0008, backfill прежних начислений и сценарии threshold, trial/cancelled, short close 25%, percent, subscription, partial/full payment, повтор урока/платежа/Assignment и конкурентный Assignment replay.
