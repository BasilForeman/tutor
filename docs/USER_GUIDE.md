# Локальный запуск и проверка бота для Сони

Бот предназначен для Сони. Доступ ограничен Telegram ID из `ADMIN_ID`; роутеры обрабатывают сообщения только при прохождении `is_admin`. Репетиторы и ученики не регистрируются. Единственная Telegram-команда — `/start`; остальные действия доступны кнопками.

## Безопасное тестовое окружение

Не используй текущую БД из `.env` для ручных проверок: она содержит рабочие данные. Используй только отдельный PostgreSQL из `docker-compose.test.yml` (порт `55433`, данные контейнера находятся в `tmpfs`). Не запускай для теста основной `docker-compose.yml`.

1. Проверь, что в `.env` настроены токен тестового бота и `ADMIN_ID` Сони. Не публикуй `.env`. Убедись, что другой экземпляр polling для этого Telegram-токена не запущен.
2. Используй виртуальное окружение `venv_new` (проверено: Python 3.12.16). Установи зависимости, если нужно:

   ```sh
   ./venv_new/bin/python -m pip install -r requirements.txt
   ./venv_new/bin/python -m pip check
   ```

3. Создай disposable БД:

   ```sh
   docker compose -f docker-compose.test.yml up -d --wait db-test
   ```

4. Создай таблицы из актуальных моделей только в ней. Переменная в начале команды переопределит значение из `.env`:

   ```sh
   DATABASE_URL='postgresql+asyncpg://tutor_test:tutor_test_only@127.0.0.1:55433/tutor_bot_test' \
     ./venv_new/bin/python create_tables.py
   ```

5. На чистой disposable БД примени миграции по порядку:

   ```sh
   for migration in migrations/[0-9][0-9][0-9][0-9]_*.sql; do
     docker compose -f docker-compose.test.yml exec -T db-test \
       psql -v ON_ERROR_STOP=1 -U tutor_test -d tutor_bot_test < "$migration" || exit 1
   done
   ```

   Миграции ручные, migration ledger отсутствует. Не запускай их повторно на существующей базе. В 0005 и 0007 удаляется и пересоздаётся только вычисляемое представление `assignment_finances`; сначала проверяй их на disposable базе.

6. Запусти бота с тестовой БД и отключёнными фоновыми отправками:

   ```sh
   DATABASE_URL='postgresql+asyncpg://tutor_test:tutor_test_only@127.0.0.1:55433/tutor_bot_test' \
   FSM_STORAGE=postgres \
   DEBT_REMINDERS_ENABLED=false \
   GOOGLE_SHEETS_SYNC_ENABLED=false \
     ./venv_new/bin/python -m bot.main
   ```

   `BOT_TOKEN` и `ADMIN_ID` берутся из `.env`. Используй тестового бота и свой ID администратора. Не нажимай **📊 Синхронизировать Sheets** во время этих сценариев. Останови polling через `Ctrl+C`.

## Ручная передача

1. Напиши `/start`, затем нажми **➕ Новая передача**.
2. Если есть активные заявки, выбери одну или **✍️ Ввести данные вручную**. Если заявок нет, ручной ввод начинается сразу.
3. Введи имя репетитора, предмет (можно пропустить), имя ученика, контакт (можно пропустить), источник и предмет/запрос (можно пропустить).
4. Введи, кто передал ученика, ставку, условия комиссии и срок оплаты (дату можно пропустить).
5. Проверь сводку и подтверди. До подтверждения записи не создаются; сохранение сущностей и передачи выполняется транзакционно.

По подтверждении активные Tutor, Client и LeadSource ищутся по имени без учёта регистра и крайних пробелов. Отсутствующие создаются. Контакт существующего ученика не перезаписывается. Lead сопоставляется по ученику, источнику и предмету; потерянная заявка не используется. Новая заявка получает историю `new`, затем при передаче — `assigned`. Повторная передача создаёт отдельный Assignment.

### Тестовые сценарии

Используй только синтетические данные с префиксом `TEST`, например `TEST Ученик 01`; не вводи контакты реальных людей. Все проверки ниже выполняй в disposable БД.

| № | Действия | Ожидаемый результат |
|---|---|---|
| 1 | На пустой БД нажать новую передачу; ввести `TEST Репетитор 01`/Математика, `TEST Ученик 01`/фиктивный контакт, `TEST Рекомендация`/Алгебра, «Соня», ставка 1500, множитель 4; срок пропустить; подтвердить. | Без активных Lead начинается ввод. Созданы Tutor, Client, Lead, Source и Assignment; Lead `assigned`, история содержит `new` и `assigned`; ставка 1500 и сохранённая комиссия 6000. Фактическое начисление следует действующему порогу платных проведённых занятий. |
| 2 | Повторить тот же набор имён, предмет и источник, но ввести другой контакт. | Используются прежние записи и Lead; появляется ещё один Assignment. Контакт Client остаётся прежним. |
| 3 | Повторить набор из №2 с другим регистром и пробелами вокруг имён/предмета. | Сопоставляются те же активные записи; новых Tutor/Client/Source/Lead нет; новая Assignment создаётся. |
| 4 | Создать передачу с новыми именами, пропустить предмет Tutor, контакт, предмет Lead и срок оплаты. | Необязательные значения остаются пустыми; после подтверждения запись создаётся. |
| 5 | На ручном вводе отправить пустое имя ученика или источника. | Бот просит исправить ввод; пустая запись не создаётся. |
| 6 | На ставке ввести `0`, отрицательное значение и текст, затем корректную сумму. | Неверные значения отклоняются. При корректной сумме сценарий продолжается; без подтверждения записей нет. |
| 7 | Нажать **❌ Отмена** по очереди на каждом шаге ручного ввода, включая имя ученика и источник. | На каждом шаге FSM очищается, бот сообщает об отмене; сущности, заявка и передача не создаются. |
| 8 | Оформить передачу для комбинации ученика/источника/предмета, у которой существует только Lead со статусом `lost`. | Потерянный Lead не переиспользуется; создаются новый Lead и Assignment. |
| 9 | Начать со списка существующих активных Lead, выбрать один, затем существующего Tutor. | Передача использует выбранные записи; повторного создания Client/Source в этом ветвлении нет. |

Ставка и согласованная сумма комиссии сохраняются при создании Assignment. Не считай их уже начисленной или оплаченной комиссией: финансовый view и ledger применяют текущие правила начисления.

### Известное ограничение схемы

В локальной схеме присутствуют старые полные уникальные ограничения `tutors_nickname_key` и `lead_sources_name_key` наряду с индексами активных имён. Поэтому архивированный Tutor или LeadSource может блокировать создание активной записи с тем же именем. Не удаляй и не переименовывай существующие данные для обхода ошибки; сначала спланируй отдельную проверенную миграцию.

Client сопоставляется по имени, не по телефону. Одинаковые имена могут привести к использованию той же карточки; автоматического сопоставления по контакту нет.

## Что сейчас доступно в Telegram

Главное меню: репетиторы, ученики, новая/список передач, завершение обучения, учёт занятий, финансы, запись платежа, корректировка комиссии, возврат платежа, источники, заявки, ручная синхронизация Sheets, аналитика.

Подменю реально подключены к handlers: создание/список/поиск/изменение/архивирование Tutor, Client и LeadSource; создание/список/поиск/фильтр/изменение Lead и смена статуса; создание/список/закрытие Assignment; Lesson, Payment, корректировка комиссии, возврат и аналитический отчёт. Дополнительные Telegram-команды для CRUD и финансов не реализованы. В текущем Implementation Plan новые Telegram-кнопки не указаны как запланированные; остаются эксплуатационные работы, включая ручной Telegram smoke test новой FSM ветки и подготовку постоянного окружения.

Для Google Sheets сверяй целевую таблицу перед ручным запуском. Автоматическая синхронизация включается только настройкой окружения. Не помещай `.env`, JSON-ключ service account или дампы БД в Git.
